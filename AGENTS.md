# Working on flint-server

`flintd` is a single Zig 0.17.0 executable, using only the standard library.
Python 3.11+ runs development tools. No database, service, npm install, or
signing key is required for development.

## Commands

Run from the repository root:

<!-- validated-commands:start -->
```sh
zig build
zig build test --summary all
python3 tools/docs.py --check
bash tools/sync-journey
python3 tools/tcp-smoke.py
```
<!-- validated-commands:end -->

- Full gate: `python3 tools/check.py`.
- Formatting, static analysis, and policies: `python3 tools/check.py --lint-only`.
- Focused test: `zig test src/store.zig --test-filter 'validators and UUID parsing'`.
- Format: `zig fmt build.zig src tools/analyze.zig`.
- Dev server: `zig-out/bin/flintd init --store=.local/store`, then
  `zig-out/bin/flintd serve --store=.local/store --listen=127.0.0.1:4748`.
- Read-only live probe: `python3 tools/healthcheck.py --address=127.0.0.1:4748`.
- `FLINT_STORE` supplies the store directory if `--store` is omitted.
  No `.env` file is loaded automatically.

## Map and contracts

- `src/store.zig`: wire/store types, bounds, refusal vocabulary.
- `src/change.zig`, `src/ed25519.zig`: canonical bytes and signatures.
- `src/storeio.zig`: crash-safe writes, append validation, recovery.
- `src/proto.zig`, `src/serve.zig`: protocol operations and transport.
- `src/conformance_test.zig`, `testdata/`: interoperability fixtures.
- `docs/flint-server-spec.md` and `docs/adr-0049.md`: normative behavior.

Preserve canonical field ordering, Go-compatible escaping, raw Change bytes,
signature preimages, refusal names, default bind address, and exit codes.
Stdout in stdio mode is exclusively protocol data. Put diagnostics on stderr.
Do not reinterpret copied ADRs as features implemented in this server.

## Conventions

Use `camelCase` for functions, `snake_case` for fields and local variables,
`PascalCase` for types, and `SCREAMING_SNAKE_CASE` only where existing code does.
Match the surrounding names for established wire fields and constants.
Keep ownership explicit with `defer`/`errdefer`; test allocation failures and
malformed inputs where relevant. Never free the same value in both paths.

Unit tests belong inline in the owning `.zig` file as descriptive named
`test "behavior being checked"` blocks. Cross-module/transport scenarios belong
in `src/conformance_test.zig`. Every bug fix should add a failing regression
test first when practical. Use `std.testing.allocator` and isolated temporary
stores, never an operator's store. Keep fixture names descriptive and golden
responses byte-identical.

## Completion and safety

Run focused tests, then `python3 tools/check.py` before completing changes.
Do not retry a failed test until green without diagnosing it; CI's repeated
runs are for detecting instability, not masking failures.

`docs/protocol-reference.md` is generated by `python3 tools/docs.py`; edit the
schema, not the generated document. Caches, reports, local stores, and binaries
must remain untracked. Do not edit signature vectors or copied ADRs to make
tests pass.

No external runtime dependencies or GPL-family code. Any proposed dependency
needs review and a seven-day release-age waiting period, including toolchain
and CI action updates (see SECURITY.md). Track deferred work in an issue;
source TODO/FIXME/HACK markers must include `(#123)` or an issue URL.

Never log request bodies, changes, key material, HMACs, nonces, authors, or
store paths. Use the dedicated logger's allowlisted fields. Do not change
GitHub settings, publish releases, or touch production stores without explicit
operator approval. See docs/runbooks/operations.md for incident procedures.
